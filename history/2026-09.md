# bootc-dev activity and agent effectiveness: August–September 2026

This is the initial baseline report, so it rolls up August and the partial month of
September in one file. September data was collected on 2026-09-16; it is not a complete
calendar month.

## Scope and data quality

- Organization: `bootc-dev`
- Activity interval: 2026-08-01 through snapshot collection on 2026-09-16 UTC
- Deterministic sources: `scripts/monthly-org-history.js` snapshots for `2026-08` and
  `2026-09`
- Repository scope: 18 visible, non-archived, non-fork repositories; no repository
  collection failures
- Issue and pull-request totals use creation or merge timestamps. Label and branch
  signals are current state on items updated in the interval, not label-event history.
- September's latest observed item update was 2026-09-16 14:05 UTC; its latest observed
  agent workflow run was 2026-09-15 23:16 UTC.

AIC coverage is incomplete. Usage artifacts had expired for most eligible runs: only 9
of 97 non-skipped agent workflow runs had readable AIC data. The 81 collection errors
were all expired-artifact HTTP 410 responses. Consequently, this report does not present
a period-wide AIC total or cost-efficiency estimate.

## Effectiveness analysis

For qualitative evidence, the review deliberately sampled linked successful work,
failed or cancelled workflows, repeated review/fix loops, unmerged agent PRs, and the
highest-AIC run. This is a targeted diagnostic sample, not a statistically representative
sample.

### Where the pipeline was effective

- [`bcvk` issue #345](https://github.com/bootc-dev/bcvk/issues/345) produced
  [PR #346](https://github.com/bootc-dev/bcvk/pull/346). The agent drafted and reviewed
  the change, a human approved it, and it merged. This is direct evidence of the intended
  issue-to-PR path completing for a bounded task.
- [`gh-agentic-workflows` issue #83](https://github.com/bootc-dev/gh-agentic-workflows/issues/83)
  produced [PR #84](https://github.com/bootc-dev/gh-agentic-workflows/pull/84). Two fix
  commits addressed action pinning and lock-file drift before human approval and merge.
- [`gh-agentic-workflows` issue #85](https://github.com/bootc-dev/gh-agentic-workflows/issues/85)
  produced [PR #86](https://github.com/bootc-dev/gh-agentic-workflows/pull/86). Protected
  workflow-file handling made human scrutiny explicit, and the approved change merged.

These cases show that the pipeline can complete bounded changes and incorporate agent,
CI, and human review feedback. They do not establish that all agent-generated work has
the same outcome.

### Guardrails worked, but exposed operational friction

- Two runs linked from [`bcvk` issue #343](https://github.com/bootc-dev/bcvk/issues/343)
  stopped at the workflow lock-file check before agent execution. A non-agent
  [PR #344](https://github.com/bootc-dev/bcvk/pull/344) repaired the stale lock file.
  This avoided spending implementation AIC against inconsistent generated files, but
  required a human recovery path.
- [`bcvk` issue #332](https://github.com/bootc-dev/bcvk/issues/332) recorded a drafter
  engine termination. The later agent [PR #342](https://github.com/bootc-dev/bcvk/pull/342)
  increased the timeout and merged, showing recovery after the initial failure.
- A cancelled review
  [run 35033775291](https://github.com/bootc-dev/gh-agentic-workflows/actions/runs/35033775291)
  was followed two minutes later by a successful replacement
  [run 35033931283](https://github.com/bootc-dev/gh-agentic-workflows/actions/runs/35033931283)
  on a newer commit. This cancellation did not become a persistent blockage.

### Difficult work still required human ownership

The highest-AIC sampled path, [`bcvk` issue #356](https://github.com/bootc-dev/bcvk/issues/356)
to [PR #357](https://github.com/bootc-dev/bcvk/pull/357), reworked an older PR. Automated
review found duplicated cleanup code and the fixer corrected it. A human then identified
missing formatting; a later review found a documentation mismatch. The workflow reached
its three-commit cap and explicitly escalated to a human. The PR remained open with
changes requested and failed checks at the cutoff.

Likewise, work stemming from
[`gh-agentic-workflows` issue #76](https://github.com/bootc-dev/gh-agentic-workflows/issues/76)
produced unmerged agent PRs [#77](https://github.com/bootc-dev/gh-agentic-workflows/pull/77)
and [#87](https://github.com/bootc-dev/gh-agentic-workflows/pull/87). A human-authored
successor, [#88](https://github.com/bootc-dev/gh-agentic-workflows/pull/88), still needed
rebase/sign-off work at the cutoff.

The evidence supports treating human review as part of the operating model, not as an
exception. Humans approved protected changes, supplied corrections, repaired workflow
state, and took ownership when automated iteration stopped.

## Recommendations

1. **Retain or aggregate AIC through the reporting window.** Preserve a durable monthly
   per-run summary, or increase usage-artifact retention, so a month-end report can cover
   substantially more than 9 of 97 eligible runs.
2. **Measure outcomes with stable linkage.** Record originating issue, generated PR,
   final disposition, and timestamps in deterministic data. This would support real
   conversion and latency metrics instead of current-state inference.
3. **Separate expected skips from failures in operational summaries.** The 281 skipped
   runs dominate raw workflow volume but mostly represent gates. Reporting activation,
   attempted execution, and outcome separately would make reliability easier to assess.
4. **Make lock-file health a rollout preflight.** The stale-lock guard prevented unsafe
   work, but repeated failures consumed human attention. Validate lock files before
   applying `agent/code` or immediately after package upgrades.
5. **Revisit the fix-loop budget for multi-step work.** PR #357 made useful progress but
   exhausted a commit-count cap. Track actual fix attempts independently of unrelated
   commits, while retaining an explicit escalation limit.
6. **Keep human approval for protected and high-impact changes.** The successful sampled
   cases used that review productively; the evidence does not support removing it.

## Limitations

- September is partial and should not be compared directly with a full month as a rate.
- Current labels and branches are not historical event logs; August's snapshot can
  reflect item state observed in September.
- The report has no complete denominator for eligible human-authored issues, no measure
  of human time, and no organization-wide end-to-end latency metric.
- A merge during the interval is not necessarily tied to a PR created during it.
- A workflow conclusion does not establish change quality or causation.
- The qualitative sample was purposefully selected for diagnostic value. Unknown
  linkage or intervention outside that sample remains unknown.
